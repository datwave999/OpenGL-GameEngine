# Resources / AssetManager

- assets are shared across entities and states, owned by Application's AssetManager
- components keep handles to this data; the renderer uses the handles to find GPU resources
- [Graphics Pipeline](2.GraphicsPipeline.md) explains how those resources are bound and drawn


## Asset Data (AssetData.h)

Data structs shared by AssetManager and the rendering code

- **Vertex**:
	- Position (vec3), Normal (vec3), TexCoords (vec2)
	- CPU data used to create the VBO
- **MeshGPU**:
	- VAO id and indexCount
	- enough information to bind the mesh and issue an indexed draw call
	- actual VAO and buffer objects are owned separately by AssetManager
- **TextureGPU**:
	- textureID: id of the openGL texture
- **MaterialAsset**:
	- shaderHandle, diffuseTextureHandle and specularTextureHandle
	- shininess and specularIntensity
	- diffuseUnit and specularUnit: texture units used when binding the textures
	- materialUBO: raw GPU buffer id (owning Buffer is stored in AssetManager)
- **ModelAsset**:
	- vector of ModelNodes
	- each node holds a meshHandle and materialHandle
	- one model can contain multiple meshes with different materials
- [IMP] asset handles are uint32_t indices into AssetManager's vectors, not openGL object ids
- connection: RenderComponent -> ModelAsset -> ModelNode -> MeshGPU + MaterialAsset -> Shader + Textures

## AssetManager class

Shared resource storage owned by Application (states access it using app->GetAssets())

- **Owns** (Private variables):
	- shaders: vector of unique_ptr(Shader)
	- meshes, textures, materials and models: vectors of asset structs
	- buffers: vector of unique_ptr(Buffer) (VBOs, EBOs and material UBOs)
	- vertexArrays: vector of unique_ptr(VertexArray)
	- caching maps for each asset type (string key -> uint32_t handle)
	- defaultTextureHandle and defaultSpecularHandle
- **Caching / Handles**:
	- loader/creator first checks its caching map
	- if key already exists: returns the existing handle
	- otherwise creates asset, adds it to the vector and stores its index in the map
	- runtime getters use the handle directly [no string map lookup in the render loop]
	- [IMP] using the same key with different arguments still returns the existing asset
	- handles remain indices as vectors grow, but pointers into vectors of asset structs can be invalidated by growth (keep handles for later access)
	- handle 0 is a valid asset index [not an invalid-handle marker]
	- handles belong to their asset type and this AssetManager instance [a mesh handle can't be used as a model handle]
	- no individual unload/reload API currently; assets stay until AssetManager is destroyed
- **Working / Life Cycle**:
	- Initialize:
		- creates a magenta 1x1 default diffuse texture and a white 1x1 default specular texture
	- LoadShader:
		- creates and stores a Shader unique_ptr from vertex and fragment paths
	- LoadTexture:
		- creates a 2D texture, sets repeating and linear filtering (mipmaps for minification)
		- loads image pixels using stbi_load
		- selects RED / RG / RGB / RGBA format from number of channels
		- sets unpack alignment to 1, uploads pixels and generates mipmaps
		- frees the CPU image data after upload
		- if loading fails: prints error, deletes GPU texture and caches a TextureGPU with id 0 [doesn't replace it with the default texture]
	- CreateTexture:
		- creates a 1x1 RGBA texture from a color (used for solid color materials and defaults)
		- uses nearest filtering and repeating
	- CreateMesh:
		- creates VAO, VBO and EBO using the graphics abstraction classes
		- uploads Vertex and index vectors using GL_STATIC_DRAW
		- configures position, normal and texture coordinate attributes
		- stores owning unique_ptrs and a MeshGPU containing VAO id + index count
		- overload accepts MeshData directly from StandardMeshes
	- CreateMaterial:
		- stores shader and texture handles with shininess and specular intensity
		- uses the default specular texture if specTex is (uint32_t)-1
		- sets diffuse texture unit to 1 and specular texture unit to 2
		- creates a 16-byte material UBO (shininess, specular intensity and two padding floats)
		- stores the owning Buffer and puts its id in MaterialAsset
	- CreateModel:
		- creates a model containing one node with the mesh and material handles passed in
	- LoadModel:
		- uses Assimp to read the model file
		- requests triangulation and smooth normals, optionally flips UVs
		- on failure: prints Assimp error and returns (uint32_t)-1
		- gets the model directory and recursively processes the scene's nodes
		- copies mesh/material data into engine assets before the local Assimp importer is destroyed
	- Getters:
		- GetShader, GetMesh, GetTexture, GetMaterial and GetModel
		- return a pointer to the asset, or nullptr if handle is out of range
		- GetDefaultTexture and GetDefaultSpecularMap return default handles
	- Destructor:
		- deletes stored openGL textures
		- Shader, Buffer and VertexArray unique_ptrs automatically delete their GPU resources when their owning vectors are destroyed

## Assimp Helpers / Model Editing

- processNode:
	- processes every mesh referenced by the current Assimp node
	- adds mesh + material handle pairs to the ModelAsset
	- recursively processes child nodes
	- [IMP] currently flattens the node hierarchy, doesn't apply Assimp node transforms
- processMesh:
	- copies positions, normals and UVs into Vertex vector (UVs default to 0 if missing)
	- copies face indices into index vector
	- starts with default diffuse/specular textures, shininess 32 and specular intensity 1
	- loads the first diffuse and specular texture if present [external files resolved from the model directory + texture filename]
	- reads shininess and averages the specular color's RGB values for specular intensity
	- creates/reuses mesh and material assets using generated cache keys
	- mesh key uses directory + mesh index, material key uses directory + material index + shader handle
	- [IMP] different model files in the same directory can generate the same keys
- SetModelNodeShader:
	- checks model handle and node index, returns (uint32_t)-1 if invalid
	- changes the shaderHandle in that node's material and returns the model handle
	- [IMP] changes the shared material, so other nodes/entities using it get the new shader too

## StandardMeshes

Generates CPU mesh data for basic shapes (static functions, no GPU resource ownership)

- **Returns**:
	- MeshData = pair of Vertex vector and index vector
	- passed to AssetManager.CreateMesh to upload it
- **Functions**:
	- CreateCube:
		- 1x1x1 cube centered at origin, separate vertices for each face
		- uvScale controls texture repetition, calculates flat normals
	- CreateSphere:
		- diameter 1 sphere centered at origin
		- sectors and stacks control resolution (defaults: 36 sectors, 18 stacks)
		- generates positions, UVs and triangle indices, then calculates smooth normals
	- CreatePlane:
		- thin box centered at origin, dimensions 1 x 0.1 x 1 in the current implementation
		- uvScale controls texture repetition, calculates flat normals
		- larger floor size comes from its entity's TransformComponent
	- CreateOverlay:
		- four vertices and six indices for a fullscreen quad (x/y from -1 to 1)
		- overlay shader uses these positions directly in clip space (doesn't use camera matrices)

## GeometryUtils

Helper functions for calculating normals from CPU mesh data (namespace with inline functions)

- CalculateFlatNormals:
	- reads each triangle's three indices
	- gets two edges, calculates and normalizes their cross product
	- assigns the same normal to all three vertices
	- used for cube and plane (different faces need separate vertices so their normals don't overwrite each other)
- CalculateSmoothNormals:
	- resets all vertex normals to 0
	- adds each triangle's cross product to the normals of its three vertices
	- normalizes the accumulated result for each vertex
	- used for sphere (vertices shared by triangles get averaged normals)
- changes the Vertex vector passed in, doesn't create or upload GPU buffers

## Using Assets in PlayState:

### Create a Mesh / Material / Model:

Example inside PlayState::Initialize(), with the existing includes for StandardMeshes:

```cpp
AssetManager& assets = app->GetAssets();

auto shader = assets.LoadShader("exampleCore",
    "assets/Shaders/core.vert", "assets/Shaders/core.frag");
auto mesh = assets.CreateMesh("exampleCube", StandardMeshes::CreateCube());
auto texture = assets.CreateTexture("exampleOrange", glm::vec4(1.0f, 0.5f, 0.0f, 1.0f));
auto material = assets.CreateMaterial("exampleMaterial", texture,
    UINT32_MAX, 32.0f, 0.5f, shader);
auto model = assets.CreateModel("exampleModel", mesh, material);

Entity object(&registry);
object.AddComponent<TransformComponent>(glm::vec3(0.0f, 1.0f, 0.0f));
object.AddComponent<RenderComponent>(model);
```

- UINT32_MAX for the specular texture requests the default white specular map
- material shininess = 32, specular intensity = 0.5
- model holds mesh/material handles; entity holds only the model handle
- another entity can use the same model with a different transform
- keys are chosen once for these resources [same key returns the existing asset, even with different arguments]

### Load an Imported Model:

```cpp
auto imported = assets.LoadModel("exampleBackpack",
    "assets/Models/backpack/backpack.obj", shader, true);

if (imported != UINT32_MAX) {
    Entity object(&registry);
    object.AddComponent<TransformComponent>(glm::vec3(2.0f, 0.0f, 0.0f));
    object.AddComponent<RenderComponent>(imported);
}
```

- uses assets and shader from the previous example, in the same initialization scope
- final true requests aiProcess_FlipUVs [choose based on the model's UV convention]
- stbi image flipping is a separate global setting; flipping image rows and flipping UVs aren't the same operation
- paths are relative to the process working directory
- image files are loaded separately from the model's directory
- AddComponent / entity lifecycle are explained in [ECS Guide](4.ECS_Guide.md#using-ecs-in-playstate)

## Current Import / Asset Limits:

- imported nodes are flattened; parent/node transforms aren't applied to the vertex data
- meshes are static [no skeletal animation or imported scene hierarchy]
- only the first diffuse/specular texture is used for each material
- texture path is reduced to its filename and resolved beside the model [subdirectories are discarded]
- embedded Assimp textures aren't handled
- normal, roughness, AO and emissive maps aren't loaded/used by this material path
- mesh/material cache keys use model directory + indices, so different models in one directory can collide
- SetModelNodeShader edits a shared material, not an independent per-entity override
- failed image load caches texture id 0; defaults are used for missing material maps, not as automatic replacements for failed files
- shader compilation/linking failure is logged, but the Shader asset is still stored
- LoadModel failure returns UINT32_MAX without storing a model
- [IMP] handles must refer to valid assets before rendering; getters can return nullptr, but the renderer doesn't check every dependency
