# Architecture Overview of the Engine

## Client runs main.cpp

- owns Application app (stack allocation)
- initializes and runs app if initialization succeeds
- enables the CRT debug heap and automatic leak checking using `<crtdbg.h>` [debug builds]
- app is destroyed when main returns, before the automatic leak report at process exit

## Entry Point to engine (Application class):

- **Owns** (Private variables):
    - window (unique_ptr): only Application owns the window
    - AssetManager assets (by value): shared with states using `app->GetAssets()`
    - State Stack vector (holds unique state ptrs): manages game states
    - internal variables for delta time and the FPS counter
- **Life Cycle Functions**:
    - Initialization:
        - creates the window and its openGL context
        - returns false if the native window wasn't created
        - initializes AssetManager's default textures
        - enables depth testing, disables VSync and enables vertical flipping for stbi image loads
        - registers Input's static callbacks with GLFW
        - pushes the first PlayState (gives it a pointer to thyself)
        - sets the starting frame time
    - Run:
        - runs while the window's close flag is false and the state stack isn't empty
        - polls events, calculates dt and updates the FPS counter/window title
        - updates the top state, then renders the visible states
        - calls Input.EndFrame and swaps buffers
    - PushState:
        - initializes the incoming state while the window/context already exists
        - moves its unique_ptr into the state stack
    - PopState:
        - removes and destroys the top state if the stack isn't empty
    - Shutdown:
        - clears all states
        - also called by Application's destructor
        - shared assets and window are released later through member destruction
- [IMP] creating states that own GPU resources needs a current openGL context (LightSystem creates its UBO in its constructor)

## The Main Window: OpenGL State

- **Responsibilities**:
    - provides the canvas to draw on (gets a window from the OS)
    - owns the GLFWwindow* and its openGL context
    - handles framebuffer resizing
- **Working / Life Cycle**:
    - Constructor:
        - initializes GLFW and requests openGL 4.6 core
        - creates the window
        - ties this C++ Window instance to GLFWwindow using its user pointer
        - [IMP] makes the context current before any openGL calls
        - loads openGL functions using GLAD + glfwGetProcAddress
        - sets the viewport to the initial width/height
        - registers the framebuffer size callback
    - framebuffer_size_callback:
        - updates the viewport
        - uses GLFW's user pointer to get the C++ Window instance
        - stores the new framebuffer width/height for the camera's aspect ratio
    - Helper Functions:
        - shouldClose: checks the window's close flag
        - pollEvents: processes GLFW events and runs registered callbacks
        - swapBuffers: displays the current back buffer
        - getting width/height and setting the window title
    - Destructor:
        - destroys the window and its context
        - terminates GLFW
- viewport controls the area rendered into; it isn't a separate window
- window creation and GLAD errors are printed [GLAD failure currently isn't fully propagated to Application]

## Handling Inputs:

- Static class: accessed globally, stores one set of input data
- Application registers key, mouse button, cursor position and scroll callbacks
- window.pollEvents -> GLFW processes events -> callbacks update Input's internal data
- callbacks run during event processing [no separate input thread]
- **Stored Data**:
    - keys/buttons: whether each is held down
    - keysChanged/buttonsChanged: whether it changed this frame
    - cursor position, mouse dx/dy and scroll dx/dy
- **Getters**:
    - getKeyState / getButtonState: held state
    - keyWentDown: held now AND changed this frame
    - keyWentUp: released now AND changed this frame
    - mouse and scroll getters: used by Camera
- **EndFrame**:
    - resets changed flags and mouse/scroll deltas
    - held key/button states remain for the next frame
- [IMP] read input before EndFrame, otherwise that frame's changes are gone
- cursor/scroll callbacks currently store the latest delta, don't accumulate all events in that frame

## Camera

Currently a standalone C++ class, owned by PlayState

- **Variables**:
    - Position, Front, Up, Right and WorldUp
    - Yaw/Pitch angles
    - movement speed, mouse sensitivity and FOV
    - camera UBO (unique_ptr(Buffer))
- **Working / Life Cycle**:
    - Constructor:
        - sets initial position and settings
        - calculates the camera vectors
        - creates its UBO while the openGL context is current
    - Update:
        - polls Input for movement, looking around and FOV changes
        - uses dt for movement speed
        - recalculates vectors if pitch/yaw changes
        - clamps pitch to -89 / +89 degrees and FOV to 1 / 110 degrees
    - UpdateUBO:
        - calculates projection/view matrices using the window dimensions and current camera data
        - uploads them to its UBO
    - Getters / Setters:
        - position, front and FOV getters
        - helpers for view/projection matrices
        - setMovementSpeed clamps negative speeds to 0
- camera matrix layout and shader usage are explained in [Graphics Pipeline](2.GraphicsPipeline.md#camera-data)
- Input and Camera currently work outside ECS

## State Base Class

Common interface inherited by PlayState and PauseState

- **Holds**:
    - protected Application* app (not owned), set by constructor
    - gives states access to assets, window and state management
- **Functions**:
    - Initialize, Update(float dt), Render: pure virtual, implemented by each state
    - isOpaque: defaults to false
    - virtual destructor: derived state is destroyed correctly through unique_ptr(State)
- Application owns the states, states only keep a pointer back to it
- [IMP] isOpaque controls rendering of lower states; only the top state is updated

## States (PlayState and PauseState):

### PlayState:

- **Owns** (Private variables):
    - Camera (unique_ptr)
    - entt::registry: owns entity IDs and component storage
    - TransformSystem, LightSystem and RenderSystem
    - entities map: named Entity wrappers for accessing specific test objects
- **Working / Life Cycle**:
    - Initialize:
        - locks and hides the cursor for FPS controls
        - loads/creates shared assets through Application's AssetManager
        - creates scene entities and adds their components
        - sets the directional light
    - Update:
        - checks ESC -> pushes PauseState and immediately returns
        - changes test entities' transforms
        - runs systems and updates Camera in the order below
    - Render:
        - delegates to RenderSystem using registry, shared assets and camera position
    - isOpaque:
        - returns true, so states below PlayState aren't rendered
- registry owns the components, Entity wrappers only reference them
- named wrappers are convenient for the current sandbox; systems can find matching entities without this map
- component details and examples are explained in [ECS Guide](4.ECS_Guide.md)

### PauseState:

- **Owns** (Private variables):
    - overlayShaderHandle and overlayMeshHandle (uint32_t)
- **Working / Life Cycle**:
    - Initialize:
        - frees the mouse cursor
        - gets overlay shader/mesh handles through AssetManager (cached if already created)
    - Update:
        - checks ESC -> recaptures the cursor and calls app->PopState()
        - popping destroys this state [don't access its members after the pop]
    - Render:
        - draws a transparent fullscreen overlay over the scene
        - changes openGL state for the overlay, then restores depth testing and disables blending
    - isOpaque:
        - returns false, allowing PlayState to render below it
- while paused: PlayState still renders, but its gameplay, camera and light updates don't run
- overlay draw details are explained in [Graphics Pipeline](2.GraphicsPipeline.md#pause-overlay)

## How Everything Connects

### Current Frame Order

- **Application.Run**:
    - polls window events (GLFW runs Input callbacks)
    - calculates dt, capped at 0.1 seconds
    - updates FPS counter/window title
    - calls Update on the top state (Application::Update)
- **if top state is PlayState**:
    - checks pause input [pushes PauseState and returns immediately if ESC was pressed]
    - Camera.Update -> handles movement/look/FOV
    - changes test entities' transforms
    - TransformSystem.Update -> recalculates dirty matrices
    - LightSystem.Update -> updates/selects lights using the camera's current position
    - Camera.UpdateUBO -> uploads the updated projection and view matrices
- **Application.Render**:
    - clears color and depth buffers once
    - finds the highest opaque state by searching from top down
    - renders from that state up to the top [if none is opaque, renders all states]
    - PlayState.Render -> RenderSystem submits the scene
    - PauseState.Render -> draws the overlay if present
- **End of Frame**:
    - Input.EndFrame resets changed flags and deltas
    - window.swapBuffers displays the frame
- [IMP] transform changes happen before TransformSystem.Update; camera movement happens before light selection and transform updates
- pushing/popping a state during Update affects which states render in the same frame

### Shared Resources / Rendering

- Application owns one AssetManager, shared across states
- components keep model handles; models reference mesh/material handles
- AssetManager owns the resources these handles refer to
- asset storage, importing and caching are explained in [3.Resources](3.Resources.md)
- RenderSystem turns matching ECS data into draws; GPU data layout and shaders are explained in [Graphics Pipeline](2.GraphicsPipeline.md)

### Ownership / Destruction Order

- main owns Application on stack
- Application owns window, AssetManager and state stack
- PlayState owns camera, registry, systems and named Entity wrappers
- registry owns entity/component storage
- Camera owns camera UBO, LightSystem owns light UBO
- Entity wrappers and asset handles don't own the objects they refer to
- **Shutdown**:
    - Application.Shutdown clears states (destroys their cameras, systems, registries and components)
    - shared assets stay alive until Application's AssetManager is destroyed
    - after Application's destructor body, members are destroyed in reverse declaration order: states -> assets -> window
    - AssetManager releases GPU resources while the window's context still exists
    - window is destroyed last, then GLFW is terminated
- [IMP] delete GPU resources before destroying their openGL context
