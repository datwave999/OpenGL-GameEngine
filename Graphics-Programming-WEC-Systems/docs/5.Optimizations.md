## Current Optimizations

*   **ECS:** EnTT packs components in storage pages and views select matching entities; separate pools don't automatically align by entity.
*   **Assets:** Four-byte model handles share resources and use indexed lookups instead of strings during rendering.
*   **Transforms:** Dirty flags skip unchanged matrix calculations, though every transform is still visited.
*   **Render queue:** Reuses capacity and sorts by shader/material, but rebuilds every render and draws each command separately.
*   **Lights:** Uses squared distances and partial sorting; uploads at most 16 point lights and 8 spotlights.
*   **Uniforms:** Caches locations, though matrices are still uploaded per draw.

## Future Optimizations

*   **Render Commands:** Shrink command layout (112 to 16 bytes) by storing asset handles and entity IDs instead of full matrices, fetching matrices during submission to avoid repeated copies.
*   **Transform Tracking:** Enqueue only changed entities for matrix rebuilds to avoid full scene scans, balancing duplicate-prevention overhead against iteration speed.
*   **Transform Data:** Split local data (position/rotation/scale) from cached matrices to improve cache locality during gameplay and lighting passes.
*   **Frustum Culling:** Test model bounds against the camera frustum to cull offscreen objects, reducing sorting, uploads, and GPU work.
*   **Instancing:** Batch visible objects sharing a mesh, material, and shader into instance buffers to reduce draw calls and per-object uniform uploads.
*   **Gameplay Updates:** Replace repeated string lookups with cached handles and transition to behavior components/systems for entities sharing movement logic.
*   **Light Components:** Shrink components by removing cached world positions and directions, deriving them dynamically from Transform data instead.
*   **Light Processing:** Cache unchanged light properties, implement spatial partitioning to reject irrelevant lights, and establish a hard influence cutoff for culling.
*   **UBO Uploads:** Optimize Uniform Buffer Object uploads by updating only changed regions rather than transferring the full fixed-size block.
* **Use SSBOs:** Transition to Shader Storage Buffer Objects (SSBOs) for uploading material and light data to the GPU, allowing for larger and more efficient data transfers.
*   **Profiling Strategy:** Measure subsystems independently (using GPU timer queries for GPU work), test against varied stress scenes, and prioritize addressing the largest overall elapsed-time bottlenecks.
*   **Shader Consolidation:** Reuse the primary `core.frag` shader for light-emitting objects by relying on new emissive maps, reducing the need to swap shader programs.
*   **Forward+ Rendering:** Implement Tiled Light Culling to drastically optimize fragment shader performance in scenes with many active lights.
